# Windows Full 2026.09.22.1

修复大历史作品文件使采集代理处理阻塞、保存回执丢失、页面反复停在第一页以及批量重复发送采集停滞通知的问题。

## 改动

- 使用内置 SQLite 按作品增量写入。原 JSON 仅用于首次迁移；保留原文件，流式读取，按作者校验记录数量和完整内容摘要。迁移事务失败或进程中断会回滚，下一次可重试；有重复 ID 或缺失 ID 的原始记录不丢弃。
- 后台迁移保持启动界面可用，视频号管理页面显示迁移状态及重试入口。OSS 历史成功记录迁移不再占用上传状态查询锁。
- 代理事件循环不执行磁盘读写；新版页面提交保存任务后查询回执。作品、回执及去重计数在同一事务提交。保存响应丢失、代理重建后可查原回执；未保存成功不能推进分页。
- 保存分页检查点，页面重连及可恢复批次重启后继续已确认位置。旧页面被新页面接替后不能继续提交。恢复游标被微信拒绝时同一作者任务只允许一次从头重采，按 ID 去重并保留已保存结果。
- 收藏作品读取、手动新增/删除、导出、中枢采集读取及 OSS 结果回写使用同一作品库。远端数据库与既有上传成功记录库职责不变。
- 五分钟无新增保存仍判定采集停滞；同批次首次告警照常发送，后续同类问题在批次结束时汇总。逐作者失败原因和作品处理结果继续保留。
- 视频号管理增加后台 SQLite 快照备份、完整 JSON 导出；代理日志增加页保存耗时与失败原因，不记录作品原始响应或游标内容。

## 升级与数据保留

1. 退出旧采集工具，安装本次 Full 安装包。默认目录仍为 `%LOCALAPPDATA%\Programs\SelfMediaContentCollector`，AppId 保持不变。
2. 如果旧版本安装在另一个目录，安装器不会自动搬移旧 `data`。首次启动前，将旧目录的 `data` 保留并复制到新目录；已有同名数据时先分别备份再核对。不要启动空数据的新目录后再覆盖数据库。
3. 新作品库保存于 `%APPDATA%\Fandow\SelfMediaContentCollector\channels_data.sqlite3`。首次启动到“视频号管理 → 本地作品库”查看迁移进度；迁移失败时显示原因，修复原因后点“重试迁移”。请勿让旧版和新版同时采集。
4. 升级后重新打开一次微信视频号页面，以载入新的保存和恢复协议。旧页面仍支持原协议，但需重开才能使用本次回执查询与断点恢复。
5. “备份作品库”或“导出完整 JSON”完成后，界面显示生成路径。文件在作品库同目录 `channels_backups` 下；可复制到其他磁盘保管。

## 恢复与回退

- 恢复新版数据库：退出软件，将当前 `channels_data.sqlite3` 及存在的 `-wal`、`-shm` 配套文件整体移到单独备份目录，然后把通过界面生成的快照复制为 `channels_data.sqlite3`。不要在软件运行时直接替换数据库，也不要把旧 WAL 配给另一份数据库。
- 回退到 JSON 版本：先在新版导出完整 JSON 并确认完成，退出软件；保留数据库和安装目录数据备份，将导出的 JSON 复制到旧版安装目录 `data/channels_parsed_feeds.json` 后再启动旧版。首次迁移保留的原 JSON 不包含新版期间的新增作品。
- 从旧版重新升级：若旧版运行期间又产生新作品，不能仅复制 JSON 后复用此前已有的 SQLite。先备份旧、新两份数据，停掉软件，移出当前 SQLite 和配套 WAL/SHM，再从准备好的最新完整 JSON 重新迁移。
- 快照或完整 JSON 只包含本地作品数据，不替代收藏配置、同步批次日志、OSS 凭据或远端数据库备份。
