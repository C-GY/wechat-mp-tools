针对 `competitor_monitor_state.json` 和 `oss_upload_tasks.json` 暴露的下载中断、错误覆盖、采集确认、数据库断连、任务恢复及失败明细丢失问题，已完成当前项目源码修复。

## 修复范围

| 原问题 | 修复后的行为 | 主要验证 |
| --- | --- | --- |
| 下载过程中 `IncompleteRead`、读超时直接失败 | 暂时性下载/上传错误最多额外重试 3 次，按 1、3、8 秒加随机抖动退避；下载失败清理临时文件，从头重新下载；不完整文件不进入上传 | 流式断连后完整重下、次数耗尽、短响应体、上传重用完整本地文件、403 不自动重试 |
| 重试不受暂停/停止控制 | 暂停后不启动新尝试，当前请求结束后确认暂停；停止取消待重试项 | 重试期间暂停、继续、停止和既有并发测试 |
| 原始错误被“缺少 OSS 链接”覆盖 | 保存失败阶段、异常类型、错误码、尝试次数和脱敏后的原始错误/堆栈；下游校验不覆盖上游失败 | 下载错误与 HTTP 错误保留、失败条目不入库 |
| MySQL 首次异常被回滚异常 `(0, '')` 覆盖 | 保留原始异常，附注回滚失败；暂时性连接/事务错误最多额外重试 2 次，每次重新连接并执行完整事务 | 读连接重建、迭代输入不被重试耗尽、提交响应丢失后的完整事务重放、认证错误不重试 |
| 采集完成通知早于持久化确认、短页提前结束 | 刷新任务 ID 关联作者及原文，实际保存成功后返回逐页 ID 回执；按分页游标继续，完成时校验去重数量和末页确认 | 实际代理 HTTP 回执、落盘失败、任务/作者错配、旧采集端缺少回执、短页仍有后续页、重复游标 |
| 部分或全旧缓存被当成本轮成功 | 保留新鲜度保护，检查上报数量与实际保存数量；采集大幅减少给出核验提示 | 旧缓存拒绝、部分缺失标记失败；单条身份无效时仍保存其他正常作品 |
| 并发采集与上传相互覆盖缓存 | 统一作品缓存读写锁，临时文件原子替换；缓存损坏时保留原文件并报错 | 同时保存采集原文与 OSS 回执，两者均保留；损坏缓存不被清空覆盖 |
| 普通退出后无法续跑 | 持久化作者采集原文、成功上传回执和已完成作者结果；重启后继续未完成任务，原已暂停任务等待手动继续 | 重启恢复、结果写入 SQLite 后 JSON 未更新的崩溃窗口、已完成作者跳过、已上传文件复用 |
| 已失败作品没有补偿入口 | 当前/历史任务提供“继续未完成项”“仅重试失败项”；失败补偿沿用原同步批次，刷新下载地址，保留可用的原观察数据 | 实际浏览器按钮 → 本地 Flask API → 补偿管线；只处理失败视频；数据库失败补偿不混入新发布作品 |
| 每位作者只保存前 100 条失败 | 完整失败明细独立保存在 SQLite，界面分页查看；状态 JSON 仅保存 3 条预览和阶段计数 | 103 条明细跨重启完整保留；浏览器 105 条明细按 50/50/5 分页；原始错误按文本转义 |
| 作者异常后计数归零、时间失真 | 保留已知采集/新增/上传数量及真实开始时间；数据库提交结果不确定显示“待核验”；重启检测时间单独保存 | 异常进度保留、数据库未知结果、原批次观察时间不变 |
| 高频进度更新重写大文件 | 网络字节进度在内存更新，磁盘写入合并至最多每 3 秒一次；状态转换、上传回执及尝试错误即时持久化 | 下载/上传/并发及恢复回归；监测轮询仅获取当前上传批次 |

新增回归测试位于 `tests/test_oss_retry.py`、`tests/test_competitor_resilience.py`、`tests/test_competitor_recovery.py`、`tests/test_capture_integrity.py` 和 `tests/test_competitor_monitor_resilience_ui.py`。

使用 `scripts/run_monitor_tests.py` 隔离导入时的状态文件，避免测试模块的全局实例加载实际用户任务。可在项目根目录复跑同一范围：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$env:COMPETITOR_MYSQL_INTEGRATION = '1'
$monitorTests = @(Get-ChildItem -LiteralPath tests -File |
    Where-Object { $_.Name -match '^test_(competitor|oss|pinchuang|capture_integrity|channels_(favorites|interaction|accounts|oss|pinchuang|author_exports))' } |
    ForEach-Object { $_.FullName })
try {
    & 'venv312/Scripts/python.exe' scripts/run_monitor_tests.py -q @monitorTests --tb=short
} finally {
    Remove-Item Env:COMPETITOR_MYSQL_INTEGRATION
}
```

上述真实数据库验证需本机配置和数据库可访问；不启用该环境变量时对应测试明确跳过。浏览器测试需 Playwright 和 Microsoft Edge。

本地诊断材料保存在 `scratch/competitor-diagnosis-2026-09-14/`：`final-verification.xml`、`reproduction-after.json`、`failures-ui.png`。该目录按项目规则不纳入版本控制。

## 使用与历史数据边界

更新后的程序首次启动会把现有失败明细迁移至状态文件旁的 `competitor_monitor_state_journal.sqlite3`。备份或迁移运行状态时，应在退出程序后一并保存 JSON 和 SQLite 文件；SQLite 还保存恢复任务所需的原文与上传回执。

运行更新后的程序并重新打开微信视频号页面，让新的采集回执协议生效。未完成任务可继续；已结算的失败项通过“仅重试失败项”补偿，成功上传对象会优先复用。网络波动恢复有次数上限，永久拒绝、失效凭据、作品已不可见等仍会保留明确失败原因。

旧日志已经截掉的 3,192 条具体错误无法重新生成。界面会明确提示历史明细缺失；针对这类作者的补偿会重新采集并与数据库比对，补齐尚无可用视频链接的作品，不声称恢复旧错误或过去未保存的互动数据。
